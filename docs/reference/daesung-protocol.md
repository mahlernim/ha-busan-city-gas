# Daesung experimental HTML discovery

Public sources inspected 2026-09-04: [issue 21 and corrections](https://github.com/mahlernim/gas-self-meter-ai/issues/21), [Daesung Energy login](https://cyber.daesungenergy.com/users/login), [Daesung Clean Energy login](https://www.daesungcleanenergy.co.kr/users/login), and [Clean Energy self-reading instructions](https://www.daesungcleanenergy.co.kr/service/self). Only public GET pages and their static scripts were fetched; no customer credentials, dummy authentication, or submission probes were used.

Observed: both login forms POST `id`, `password`, and `returl` to `/users/login`. Both link to `/charge/month`. Energy links to `/consult/self`; Clean Energy separately links to `/service/self_input`. Public JavaScript contains UI validation, while customer billing and input HTML require authentication. Similar login forms do not establish identical backend DTOs.

Implemented practical runtime assumptions: discover a uniquely labelled customer-number select/input in authenticated HTML; parse monthly tables by Korean column labels; discover meter period, previous reading, and meter serial labels; select one POST form containing a labelled current-reading input and explicit meter registration button. Submission carries the fresh form's hidden controls and selected contract. Discovered actions must remain on that company's HTTPS origin and beneath its specific self-reading path. Enrollment/payment/cancellation routes are not followed. JavaScript-only actions or ambiguous forms stop with a safe schema error.

Customer HTML fixtures are synthetic and are **not** captured actual provider pages. The adapter is usable experimental discovery, not a claim that all authenticated layouts have been verified. Dates, identifiers and payloads must come from the user's actual page; none are invented. An HTTP 200 or unfamiliar acknowledgement does not claim success: every attempted write stays uncertain until the coordinator reads the official meter page and matches the submitted value. Writes never retry automatically.

Account fields: ordinary website username and password. A separate customer-number field is not required when the authenticated portal exposes its contract selector. Initial billing implementation reads the currently served monthly ledger and preserves prior cached months; it does not fabricate a historical date-range query. Missing billing fields remain unavailable.
